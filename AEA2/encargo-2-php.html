Encargo 2 · Portal dinámico con PHP

Punto de Juego incorpora su primera página generada en el servidor.

Entrega 2Apache + PHP-FPMSin base de datos

El cliente quiere avanzar

Punto de Juego

«Ya tenemos una primera web. Ahora queremos que el listado de actividades se construya a partir de una lista de datos, para no repetir manualmente la estructura HTML cada vez que añadimos un encuentro. Os damos un prototipo PHP y necesitamos que funcione en el servidor que ya habéis preparado».

Esta entrega incorpora generación de contenido en el servidor. No incluye formularios, inscripciones reales ni base de datos.

Descargar el prototipo PHP · ZIP

Resultado esperado

Los tres integrantes deben tener el portal PHP funcionando mediante Apache HTTP Server en su ordenador. El código y la identidad visual se comparten; la configuración, pruebas y explicación son individuales.

La referencia de integración es Apache + PHP-FPM. PHP en el terminal o su servidor integrado no sustituyen el despliegue del encargo. Si ya tienes otra integración configurada, identifícala y acuerda el cambio con el docente antes de modificarla.

1 · Preparar la nueva versión

  1. Descargad y revisad el ZIP: identificad qué es código PHP, qué es HTML y qué es presentación visual.
  2. Incorporad esta versión al mismo repositorio, conservando identificable la entrega estática mediante el historial y una carpeta o etiqueta acordada.
  3. Leed la lista de actividades y el bucle. Explicad qué ocurre al añadir un elemento.
  4. Preparad una rama o distribución de tareas y un criterio para integrar los cambios de los tres miembros.

El README del paquete explica su estructura. La teoría de PHP contiene los conceptos necesarios.

2 · Preparar PHP y conectarlo con Apache

  1. Identificad distribución, versión de Apache e instalaciones previas de PHP.
  2. Consultad la documentación de vuestra distribución e instalad los componentes necesarios para ejecutar PHP con PHP-FPM.
  3. Identificad servicio FPM, versión, configuración y socket o punto de escucha local.
  4. Identificad y habilitad los módulos de comunicación de Apache necesarios, como proxy y proxy_fcgi. No son mod_php y no ejecutan el código PHP.
  5. Configurad qué peticiones debe remitir Apache a PHP-FPM y el socket que utilizará. Comprobad que coincide con el punto de escucha del servicio. No expongáis FPM a la red.
  6. Comprobad las configuraciones antes de recargar los servicios y verificad que ambos están disponibles.
  7. Registrad qué habéis cambiado y cómo se relacionan Apache y PHP.

Los nombres de paquetes y servicios no son iguales en Ubuntu y Fedora. Debéis encontrar los correspondientes a vuestro entorno y justificar los pasos, no copiar una receta de otra instalación.

3 · Desplegar y personalizar

  1. Publicad el contenido de public/ en la ubicación acordada y mantened la documentación fuera de esa carpeta pública.
  2. Conservad una forma de volver a la entrega estática. Evitad que un index.html anterior oculte el index.php.
  3. Aplicad a la nueva versión la identidad de Punto de Juego que preparasteis en el encargo 1.
  4. Añadid al menos una actividad a la lista proporcionada, para disponer de tres. Elegid textos coherentes con vuestra propuesta.
  5. Guardad e integrad los cambios de forma que las tres copias ejecuten la misma versión del portal.

La personalización PHP se limita a los datos de la lista. No es necesario reescribir el bucle ni la función de escapado.

4 · Probar la ejecución y documentarla

PruebaQué debes demostrar
Acceso HTTP a index.phpResponde el portal esperado a través de Apache, con su CSS.
Contenido generadoSe muestran los elementos de la lista; añadir uno genera otro bloque sin duplicar el HTML de la plantilla.
Comparación de respuestasLa hora cambia en dos respuestas separadas, con la caché desactivada.
Código fuente recibidoEl navegador recibe HTML, sin código PHP ni instrucciones del bucle.
Entorno de ejecuciónIdentificas las versiones y la integración usada. php -v por sí solo no demuestra ejecución web.
URL del directorioEl documento inicial conduce a la versión PHP prevista.
Incidencia y recuperaciónRelacionas un síntoma con una comprobación, una corrección y una nueva prueba.

Actualiza tu documento individual en Markdown: entorno, requisitos, configuración, procedimiento reproducible, URL local, pruebas, decisiones, fuentes e incidencias. Incluye comandos realmente utilizados y explica su función.

Conserva pruebas de tu ordenador, no solo capturas de un compañero. No entregues un phpinfo() completo ni publiques credenciales.

Entrega y explicación individual

  • Repositorio común con la nueva versión, README actualizado y contribuciones identificables.
  • Evidencias Markdown de cada integrante, enlazadas desde el README.
  • Portal PHP desplegado y funcionando en los tres ordenadores.
  • Explicación del recorrido de la petición y de la diferencia entre código fuente, respuesta HTML y datos persistentes.

Encargo conseguido

Puedes demostrar la generación de HTML por PHP, identificar el servicio que lo ejecuta y explicar cómo reproducir el despliegue con tu documentación.

Criterios principales: 1.2, 1.3, 1.6, 1.7, 1.8 y 1.9. Esta práctica introduce ejecución de aplicaciones; la instalación de Tomcat se evaluará en su entrega correspondiente.

Si terminas antes

  • Mejora la vista móvil y la navegación con teclado, conservando la plantilla PHP funcional.
  • Añade un campo sencillo a las actividades, como municipio, y muéstralo siguiendo el patrón de escapado proporcionado.
  • Prueba en una copia un título que contenga < o & y explica por qué aparece como texto.
  • Comprueba si CLI y FPM usan la misma versión y explica qué evidencias permiten afirmarlo.

Elige una mejora, compruébala y documéntala. No añadas todavía MariaDB ni cambies de tecnología.
