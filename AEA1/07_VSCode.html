7 · VS Code como interfaz de Git

Git sin salir del editor

Visual Studio Code ofrece una interfaz visual para el mismo repositorio Git que utilizas desde el terminal: cambios, staging, commits, ramas y sincronización.

La interfaz no sustituye a Git

VS Code utiliza la instalación de Git de tu ordenador. No crea un repositorio distinto ni una copia especial: los comandos del terminal y la interfaz gráfica trabajan sobre los mismos archivos, staging, ramas y commits.

Source Control

La vista de control de código fuente reúne los archivos modificados, preparados y los comandos habituales.

Diff visual

Al pulsar un archivo modificado, puedes comparar su versión guardada con tus cambios línea a línea.

Rama activa

En la barra inferior aparece la rama actual. Desde ahí puedes crear o cambiar de rama.

Idea clave

Si haces un commit desde VS Code, aparecerá al ejecutar git log. Si haces git add desde el terminal, VS Code mostrará el archivo en la sección Staged Changes.

1 · Abrir el repositorio

Empieza siempre por la carpeta correcta

Abre en VS Code la carpeta raíz del proyecto, aquella que contiene la carpeta oculta .git. Ve a File → Open Folder… y selecciónala. Al detectarla, VS Code activará automáticamente el icono de Source Control en la barra lateral.

code .git status

Si tienes el comando code disponible, puedes abrir el proyecto desde su carpeta con code .. Comprueba después que VS Code y git status muestran la misma rama y los mismos cambios.

No aparece Source Control

Comprueba que Git está instalado ejecutando git --version en el terminal integrado y que abriste la carpeta del repositorio, no solo un archivo.

Proyecto ajeno

Si has descargado un proyecto de Internet, lee el aviso de confianza del espacio de trabajo antes de ejecutar tareas o extensiones.

2 · Cambios, staging y commit

El flujo de Git, con botones

Abre la vista Source Control. Los archivos aparecen agrupados según su estado, igual que en git status.

Changes

Son cambios sin preparar: equivalen a archivos modificados o sin seguimiento en tu directorio de trabajo.

Staged Changes

Pulsa el símbolo + junto a un archivo para añadirlo al staging. Es equivalente a git add nombre-archivo.

Commit

Escribe un mensaje descriptivo en la caja superior y pulsa Commit. Es equivalente a git commit -m "mensaje".

Pulsa un archivo para abrir el comparador: las líneas eliminadas aparecen a un lado y las añadidas al otro. Revisa ese diff antes de añadir un archivo al staging.

No pulses “Stage All” por costumbre

Antes revisa los archivos. Preparar solo lo que pertenece al siguiente commit mantiene el historial claro y evita publicar cambios accidentales.

3 · Ramas e historial

Trabaja en una rama desde la barra inferior

Haz clic en el nombre de la rama de la barra de estado, en la parte inferior izquierda. Puedes seleccionar una rama existente o elegir Create new branch…. VS Code cambia los archivos del proyecto igual que git switch nombre-rama.

git branchgit switch -c feature/mejora-readmegit log --oneline --graph --all

El gráfico de Source Control permite consultar los commits y las relaciones entre ramas. Aun así, usa el terminal cuando quieras comprobar con precisión el historial, resolver un problema o aprender qué orden ha seguido Git.

Antes de cambiar

Confirma, guarda temporalmente o descarta los cambios pendientes. Cambiar de rama con archivos modificados puede impedir el cambio o trasladar cambios no confirmados.

Conflictos

VS Code muestra acciones para aceptar el cambio actual, el entrante o ambos. Lee el resultado final: resolver no consiste en pulsar un botón sin revisar.

4 · GitHub desde VS Code

Sincronizar, publicar y Pull Requests

Las acciones básicas de Git —clonar, pull y push— ya están integradas. Para crear o revisar Pull Requests desde el editor instala la extensión oficial GitHub Pull Requests and Issues e inicia sesión con tu cuenta de GitHub.

Sincronizar cambios

El botón Sync Changes primero trae los cambios remotos y después publica los tuyos. Si prefieres controlar el orden, usa las opciones separadas Pull y Push.

Publicar rama

Cuando una rama no existe todavía en GitHub, usa Publish Branch. Equivale a git push -u origin nombre-rama.

git pullgit pushgit push -u origin feature/mejora-readme

La extensión de Pull Requests es útil, pero no obligatoria: también puedes crear la PR desde la web de GitHub. Elige una sola interfaz para cada paso y comprueba siempre la rama origen y la rama destino.

Práctica

Repite un flujo de Git usando VS Code

  1. Abre en VS Code el repositorio que ya utilizas en clase y entra en Source Control.
  2. Modifica una línea de tu README.md o añade una breve sección de tecnologías.
  3. Abre el archivo desde Changes, revisa el diff y añádelo al staging pulsando +.
  4. Escribe un mensaje de commit claro y confirma el cambio desde VS Code.
  5. Comprueba en el terminal integrado que el commit existe con git log --oneline -3.
  6. Publica el commit con Push o Sync Changes y verifica en GitHub que aparece en el historial.
