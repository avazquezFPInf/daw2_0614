GitHub i remots

Chuleta para conectar, publicar y sincronizar tu repositorio con GitHub.

1. Crear el repositorio en GitHub

  1. En GitHub, selecciona New repository.
  2. Elige un nombre claro y crea el repositorio vacío: no marques README, .gitignore ni licencia si ya tienes el proyecto local.
  3. Copia la URL HTTPS del repositorio, por ejemplo: https://github.com/usuario/proyecto.git.

2. Conectar y hacer el primer push

git remote add origin https://github.com/usuario/proyecto.git
# Conecta el repositorio local con GitHub. “origin” es el nombre habitual del remoto principal.

git remote -v
# Comprueba la dirección configurada para enviar y recibir cambios.

git branch -M main
# Renombra la rama actual a main, que será la rama principal.

git push -u origin main
# Publica main en GitHub por primera vez y deja configurado el seguimiento remoto.

3. Trabajo diario con GitHub

git pull
# Descarga e incorpora los cambios de GitHub antes de empezar a trabajar.

git status
# Comprueba el estado local después de modificar archivos.

git add .
# Prepara los cambios revisados para el próximo commit.

git commit -m "Actualiza el contenido de la portada"
# Guarda una versión local con un mensaje claro.

git push
# Envía los commits locales a la rama remota configurada.

Si trabajas sola/o y siempre desde el mismo equipo, este es el flujo habitual. Si hay más personas, haz git pull antes de modificar archivos.

4. Clonar un repositorio existente

git clone https://github.com/usuario/proyecto.git
# Descarga el repositorio completo, incluido su historial, en una carpeta nueva.

cd proyecto
# Entra en la carpeta creada por clone.

git remote -v
# Comprueba que clone ya configuró origin automáticamente.

5. Ramas y Pull Request

git switch -c feature/menu
# Crea la rama feature/menu y cambia a ella para trabajar sin tocar main.

git push -u origin feature/menu
# Publica la rama en GitHub y configura su seguimiento.

git switch main
# Vuelve a la rama principal.

git pull
# Actualiza main antes de integrar o continuar trabajando.

git branch
# Lista las ramas locales y marca con * la rama activa.

En GitHub abre una Pull Request desde feature/menu hacia main. Describe el cambio, revisa los archivos y fusiona solo cuando el resultado sea correcto.

Seguridad y dudas frecuentes

  • No subas contraseñas, claves API ni datos personales sensibles.
  • git pull trae cambios; git push envía tus commits; git clone obtiene una copia completa por primera vez.
  • Si Git pide autenticación por HTTPS, inicia sesión en el navegador o usa un token de acceso personal; nunca uses la contraseña de GitHub en la terminal.
