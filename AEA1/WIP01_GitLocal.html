Git local

Chuleta de instalación, configuración y trabajo diario sin conexión a GitHub.

1. Instalar y comprobar Git

Windows: instala Git desde git-scm.com y abre Git Bash o la terminal de VS Code.

macOS: instala las Command Line Tools cuando Terminal lo solicite con git --version.

Ubuntu/Debian: sudo apt install git.

git --version
# Comprueba que Git está instalado y muestra su versión.

2. Configuración inicial · solo una vez

git config --global user.name "Nombre Apellido"
# Indica el nombre que aparecerá como autor de tus commits.

git config --global user.email "tu.correo@ejemplo.com"
# Indica el correo asociado a tus commits; usa el mismo que en GitHub.

git config --global --list
# Muestra la configuración global para comprobar nombre y correo.

3. Crear el repositorio local

cd ruta/de/tu/proyecto
# Entra en la carpeta del proyecto.

git init
# Crea el repositorio Git local y la carpeta oculta .git.

git status
# Muestra los archivos modificados, preparados o pendientes de confirmar.

git add index.html
# Añade solo index.html a staging para el próximo commit.

git add .
# Añade todos los cambios del directorio actual a staging. Revisa antes con status.

git commit -m "Crea estructura inicial de la web"
# Guarda una versión de los cambios preparados con un mensaje descriptivo.

4. Flujo diario · crear versiones

git status
# Primero: revisa qué ha cambiado.

git diff
# Muestra las diferencias todavía no añadidas a staging.

git add nombre-del-archivo.html
# Selecciona exactamente el archivo que formará parte del commit.

git diff --staged
# Revisa por última vez lo que entrará en el commit.

git commit -m "Añade sección de objetivos"
# Crea una nueva versión. El mensaje explica qué cambia, en presente y de forma concreta.

git log --oneline
# Muestra un historial resumido: identificador y mensaje de cada commit.

Haz un commit cuando completes una unidad de trabajo coherente: no al final de todo el proyecto ni después de cada letra escrita.

5. Consultar y corregir sin perder trabajo

git show
# Muestra el contenido y los cambios del último commit.

git restore nombre-del-archivo.html
# DESCARTA los cambios locales no guardados de ese archivo. Úsalo solo si estás seguro.

git restore --staged nombre-del-archivo.html
# Saca un archivo de staging, pero conserva los cambios en el archivo.

git mv antiguo.html nuevo.html
# Renombra un archivo y prepara el cambio para el siguiente commit.

git rm archivo.html
# Elimina un archivo y prepara la eliminación para el siguiente commit.

Primer push

El primer envío a GitHub necesita crear antes el repositorio remoto. Sigue la chuleta de GitHub y remotos. Cuando termines, el flujo diario será: git pull → modificar → git add → git commit → git push.
