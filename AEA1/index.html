Introducció

Bones pràctiques de programació

El codi també comunica. Noms significatius, una estructura ordenada i comentaris útils permeten que l'equip pugui entendre, modificar i mantenir el projecte.

Noms significatius

preuFinal explica més que x. Cada nom ha d'ajudar a entendre la finalitat de la variable, funció o classe.

Comentaris que aporten context

No repeteixen el codi: expliquen el perquè d'una decisió, una limitació o un comportament no evident.

Un llenguatge de marcat lleuger per escriure documentació tècnica, README, incidències i apunts de projecte.

Activitat · crea perfil.md

  1. Escriu un títol, una presentació i les tecnologies que coneixes.
  2. Afegeix llistes, un enllaç, una taula, un bloc de codi, una cita i una checklist.
  3. No incloguis dades personals sensibles.
  4. Previsualitza el fitxer a Visual Studio Code abans de fer commit.

1 · Sessions 3 i 4

Git local

Git evita carpetes com projecte_final2: guarda instantànies del projecte, permet revisar l'historial i recuperar versions anteriors.

Repositori, working directory i staging

El directori de treball és on edites. La staging area selecciona els canvis exactes del proper commit; el repositori desa l'historial.

Del canvi al commit

Un commit ha de ser petit, coherent i descriure la finalitat del canvi. Revisa sempre el canvi abans d'afegir-lo.

git initgit statusgit diffgit add nom-fitxer.mdgit commit -m "Missatge descriptiu"git log --oneline

Inclou un .gitignore per als fitxers temporals, generats o sensibles. Les contrasenyes i claus no s'han de versionar mai.

2 · Sessió 5

GitHub i remots

Git manté l'historial al teu ordinador. GitHub allotja repositoris Git i afegeix eines de col·laboració, permisos, Pull Requests, Pages i Actions.

Flux amb el remot

push envia commits a GitHub; pull incorpora canvis al teu ordinador; clone descarrega un repositori complet per primera vegada.

Fork i seguretat

Un fork crea una còpia d'un repositori aliè al teu compte. Revisa què és públic i evita pujar dades personals o credencials.

git remote -vgit remote add origin URLgit branch -M maingit push -u origin maingit pullgit clone URL

3 · Sessió 6

VS Code i documentació

La vista Source Control mostra els fitxers modificats. Entén el flux abans d'usar els botons: modificar, revisar, afegir, commit i push.

Control de canvis

Compara el diff visual de VS Code amb git diff. El botó + fa staging, Commit crea una instantània i Sync sincronitza amb el remot.

README.md

És la porta d'entrada del repositori: títol, descripció, estructura, instruccions bàsiques i enllaços a la documentació.

4 · Sessions 7 i 8

Branques i col·laboració

La branca principal, normalment main, manté una versió estable. Crea una branca per a un canvi important i integra-la quan estigui preparada.

git switch -c feature/menugit switch maingit merge feature/menugit log --oneline --graph --all

Merge i conflictes

Si Git no pot decidir quina versió conservar, llegeix el conflicte, elimina els marcadors, deixa el fitxer coherent, fes add i crea el commit de resolució.

Pull Request

La persona autora explica el canvi; una altra el revisa i comenta abans d'integrar-lo. El canvi i la revisió queden registrats.

5 · Sessió 9

Javadoc

Javadoc genera una web de documentació HTML a partir dels comentaris del codi Java. El mateix principi existeix en molts altres llenguatges.

/**
 * Calcula el preu final d'una comanda.
 * @param preu preu inicial
 * @param descompte percentatge aplicat
 * @return preu final
 */

Un comentari de documentació explica què fa l'element, quines dades rep i què retorna; no repeteix línia per línia el codi.

javadoc -d docs src/*.javaObre docs/index.html al navegador

6 · Sessió 10

Publicació i integració contínua

GitHub Pages

Publica una web estàtica des de la branca main. Comprova els enllaços en una finestra privada i afegeix l'adreça pública al README.

GitHub Actions

Executa comprovacions automàtiques a cada push o Pull Request. Localitza el workflow, entén quan s'executa i interpreta el resultat.

Tancament

  1. Comprova que git status no mostra canvis pendents.
  2. Revisa que l'historial mostra una evolució real.
  3. Verifica web publicada i workflow correcte.
  4. Entrega a Moodle l'enllaç al repositori i a la web.
