8 · Publicación con GitHub Pages

Convierte tu repositorio en una web

GitHub Pages publica los archivos HTML, CSS y JavaScript de tu repositorio para que tu proyecto tenga una URL pública.

¿Qué es GitHub Pages?

Es un servicio de alojamiento para sitios estáticos. Toma los archivos de una rama o de una carpeta de tu repositorio y genera una web sin que tengas que contratar un servidor.

Sí puede publicar

HTML, CSS, JavaScript, imágenes, fuentes y archivos estáticos de una web.

No ejecuta

PHP, Node.js en servidor, bases de datos ni formularios con lógica propia de servidor.

Se actualiza con Git

Cuando haces push a la fuente de publicación, GitHub vuelve a generar el sitio.

Antes de publicar

La web quedará accesible desde Internet. No subas contraseñas, tokens, datos personales de terceros ni archivos que no deban ser públicos.

Dos tipos de dirección

La URL depende del nombre del repositorio

Web de proyecto

Es la opción que usarás normalmente. Si tu usuario es alumna y el repositorio se llama portfolio, la dirección será:

https://alumna.github.io/portfolio/

Web personal

Solo se crea si el repositorio se llama exactamente usuario.github.io. En ese caso, la dirección será:

https://usuario.github.io/

Para los proyectos de clase utilizaremos una web de proyecto. Recuerda este detalle al escribir enlaces: una ruta que empieza por / apunta al dominio completo y puede perder el nombre del repositorio.

<!-- Recomendado dentro de un proyecto publicado -->
<link rel="stylesheet" href="css/styles.css">
<img src="assets/foto.png" alt="Descripción">

<!-- Evítalo si la web está en /nombre-repositorio/ -->
<link rel="stylesheet" href="/css/styles.css">

1 · Preparar el repositorio

Comprueba que la web puede abrirse

GitHub Pages busca un archivo de inicio llamado index.html en la carpeta que selecciones como fuente. Antes de publicar, abre ese archivo en el navegador desde tu ordenador y revisa:

Archivo inicial

Existe un index.html en la raíz del proyecto o en la carpeta que vas a publicar.

Rutas relativas

Las hojas de estilo, imágenes, scripts y enlaces entre páginas usan rutas relativas correctas.

Cambios confirmados

Todo está guardado, añadido, confirmado y enviado a GitHub con git push.

git statusgit add .git commit -m "feat: publica la web inicial"git push

2 · Activar GitHub Pages

Publicar desde una rama

  1. En GitHub, abre el repositorio que contiene la web.
  2. Entra en Settings y, en el menú lateral, pulsa Pages.
  3. En Build and deployment, selecciona Deploy from a branch.
  4. Elige la rama main —o la rama que utilices— y la carpeta /(root).
  5. Pulsa Save. GitHub preparará la publicación.
  6. Espera a que aparezca la URL del sitio y ábrela en una pestaña nueva.

No aparece la web de inmediato

La primera publicación puede tardar unos minutos. En la pestaña Actions puedes comprobar si el proceso de despliegue ha terminado correctamente o si informa de algún error.

3 · Actualizar el sitio

Tu flujo habitual ya publica la nueva versión

Una vez configurada la fuente, no tienes que volver a activar Pages. Trabaja como siempre: modifica, revisa, confirma y publica los cambios. Cada push a la rama y carpeta seleccionadas inicia una nueva publicación.

git statusgit add .git commit -m "feat: actualiza portada"git push origin main

Después abre la URL de GitHub Pages y recarga la página. Si no ves la versión nueva, espera a que finalice el proceso de Actions y haz una recarga forzada del navegador.

Introducción a GitHub Actions

La automatización que hay detrás

GitHub Actions ejecuta tareas automáticas cuando ocurre algo en el repositorio, por ejemplo al hacer push o al abrir una Pull Request. Para publicar desde una rama no necesitas escribir ningún archivo de configuración: GitHub gestiona el despliegue de Pages.

Ahora

Usa la pestaña Actions para comprobar el estado de la publicación y entender que cada ejecución tiene un resultado.

Más adelante

Un workflow puede validar enlaces, ejecutar pruebas o construir un proyecto antes de publicarlo. Se define en archivos YAML dentro de .github/workflows/.

Práctica final

Publica tu portfolio o proyecto web

  1. Comprueba que el repositorio contiene un index.html y que la web funciona localmente.
  2. Revisa las rutas de CSS, JavaScript, imágenes y enlaces. Usa rutas relativas.
  3. Confirma y publica los cambios en la rama main.
  4. Activa GitHub Pages desde Settings → Pages, seleccionando main y /(root).
  5. Espera a que termine el despliegue, visita la URL y comprueba cada página y cada imagen.
  6. Añade al README.md un enlace con el texto Ver la web publicada.
  7. Entrega por Moodle el enlace del repositorio y el enlace de GitHub Pages.
